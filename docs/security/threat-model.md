# 脅威モデル (STRIDE分析)

## システム概要

**アプリケーション**: YouTube市場調査システム (yt-mkt)
**アーキテクチャ**: Next.js (App Router) + NextAuth.js + Google APIs
**データフロー**:
```
ユーザー → Next.js App → NextAuth.js → Google OAuth 2.0
                      ↓
              Google Sheets API
              YouTube Data API
                      ↓
              ユーザーのGoogleドライブ
```

---

## 資産 (Assets)

| 資産 | 機密性 | 完全性 | 可用性 | 影響度 |
|------|--------|--------|--------|--------|
| Googleアクセストークン | 高 | 高 | 中 | 致命的 |
| ユーザーのYouTubeデータ | 中 | 中 | 中 | 高 |
| スプレッドシートデータ | 中 | 高 | 中 | 高 |
| OAuth Client Secret | 高 | 高 | 低 | 致命的 |
| セッションJWT | 高 | 高 | 中 | 高 |
| YouTube API クォータ | 低 | 中 | 高 | 中 |

---

## STRIDE分析

### S: Spoofing (なりすまし)

#### 脅威 S-1: OAuth認証フローの中間者攻撃
**説明**: 攻撃者がOAuthコールバックを傍受し、認可コードを盗む
**影響**: ユーザーアカウントへの不正アクセス
**リスク**: 高
**対策**:
- ✅ HTTPS強制 (Vercelデフォルト)
- ✅ state パラメータによるCSRF対策 (NextAuth.jsデフォルト)
- ✅ PKCE (Proof Key for Code Exchange) の使用
- ✅ 承認済みリダイレクトURIの厳密な設定

#### 脅威 S-2: セッショントークンの盗用
**説明**: XSSやネットワーク盗聴によるJWTトークンの窃取
**影響**: セッションハイジャック
**リスク**: 高
**対策**:
- ✅ HttpOnly Cookie でのJWT保存
- ✅ Secure フラグの設定 (HTTPS環境)
- ✅ SameSite=Lax または Strict
- ✅ 短い有効期限 (15分推奨)
- ✅ リフレッシュトークンのローテーション

#### 脅威 S-3: Googleアカウントのなりすまし
**説明**: 盗まれた認証情報での不正ログイン
**影響**: ユーザーデータへの不正アクセス
**リスク**: 中
**対策**:
- ✅ Google側のMFA推奨をユーザーに案内
- ✅ 異常なログインパターンの検出 (IPアドレス、UAの変化)
- ✅ セッションの定期的な再検証

---

### T: Tampering (改ざん)

#### 脅威 T-1: APIリクエストの改ざん
**説明**: ブラウザからのAPIリクエストを改ざんし、他ユーザーのデータにアクセス
**影響**: データの不正取得・変更
**リスク**: 高
**対策**:
- ✅ サーバーサイドでの認証・認可チェック (全APIエンドポイント)
- ✅ リクエストパラメータのバリデーション (スキーマ検証)
- ✅ CSRF トークンの検証
- ✅ ユーザーIDとリソースIDの関連性チェック (IDOR防止)

#### 脅威 T-2: スプレッドシートデータの直接改ざん
**説明**: ユーザーがスプレッドシートを直接編集し、不正なデータを注入
**影響**: データ整合性の破壊、XSSの可能性
**リスク**: 中
**対策**:
- ✅ スプレッドシートから読み取ったデータのサニタイズ
- ✅ データ型・範囲のバリデーション
- ✅ 重要な計算はサーバーサイドで再実行
- ⚠️ ユーザーへの注意喚起 (スプレッドシートの直接編集リスク)

#### 脅威 T-3: JWTトークンの改ざん
**説明**: JWTの署名を偽造し、権限を昇格
**影響**: 権限昇格
**リスク**: 低 (署名検証があれば)
**対策**:
- ✅ 強力な署名アルゴリズム (HS256 or RS256)
- ✅ 秘密鍵の厳重な管理 (環境変数)
- ✅ "alg: none" 攻撃への対策 (NextAuth.jsはデフォルトで対策済み)

---

### R: Repudiation (否認)

#### 脅威 R-1: 不正操作の否認
**説明**: ユーザーが自身の操作を否認し、セキュリティインシデントの調査を妨害
**影響**: インシデント対応の困難
**リスク**: 低
**対策**:
- ✅ 重要操作のログ記録 (認証、データ変更)
- ✅ タイムスタンプとユーザーIDの記録
- ✅ ログの改ざん防止 (append-only, 外部ログサービス)
- 📝 監査ログの保持期間の定義 (90日推奨)

#### 脅威 R-2: API操作の追跡不能
**説明**: YouTube/Sheets API の操作履歴が記録されず、不正利用を追跡できない
**影響**: API クォータ乱用、不正利用の検出不能
**リスク**: 中
**対策**:
- ✅ API呼び出しのログ記録 (エンドポイント、ユーザー、タイムスタンプ)
- ✅ クォータ消費量のトラッキング
- ✅ 異常なAPI使用パターンのアラート

---

### I: Information Disclosure (情報漏洩)

#### 脅威 I-1: エラーメッセージによる情報漏洩
**説明**: 詳細なエラーメッセージがスタックトレースや内部情報を露出
**影響**: システム構造の露出、攻撃面の拡大
**リスク**: 中
**対策**:
- ✅ 本番環境では一般的なエラーメッセージのみ返す
- ✅ 詳細なエラーはサーバーログに記録
- ✅ Next.js の NODE_ENV=production 設定
- ✅ カスタムエラーページの実装

#### 脅威 I-2: APIレスポンスの過剰な情報
**説明**: APIが必要以上の情報を返し、機密データが漏洩
**影響**: ユーザーデータの漏洩
**リスク**: 中
**対策**:
- ✅ レスポンスフィールドのホワイトリスト化
- ✅ 他ユーザーのデータを含まないことを検証
- ✅ OAuth トークンやシークレットをレスポンスに含めない
- ✅ Googleアクセストークンはサーバーサイドのみで保持

#### 脅威 I-3: ログへの機密情報出力
**説明**: アクセストークン、API キーがログに記録される
**影響**: 認証情報の漏洩
**リスク**: 高
**対策**:
- ✅ トークン、パスワード、APIキーをログに出力しない
- ✅ ログ出力時のマスキング処理
- ✅ 環境変数の値をログに含めない
- ✅ Vercel ログの適切なアクセス制御

#### 脅威 I-4: クライアントサイドへのシークレット露出
**説明**: 環境変数がブラウザに露出し、APIキーが漏洩
**影響**: APIキーの不正利用
**リスク**: 致命的
**対策**:
- ✅ `NEXT_PUBLIC_` プレフィックスの慎重な使用
- ✅ OAuth Client Secret はサーバーサイドのみ
- ✅ YouTube API キーもサーバーサイドのみ
- ✅ ブラウザDevToolsでのネットワークタブの監視

#### 脅威 I-5: スプレッドシートの不適切な共有
**説明**: ユーザーがスプレッドシートを誤って公開設定にする
**影響**: ユーザーデータの公開
**リスク**: 中
**対策**:
- ✅ スプレッドシート作成時にプライベート設定を明示
- ⚠️ ユーザーへの注意喚起 (共有設定の確認)
- 📝 スプレッドシートに機密データを含めない設計

---

### D: Denial of Service (DoS)

#### 脅威 D-1: API クォータの枯渇攻撃
**説明**: 大量のリクエストでYouTube API クォータを消費させる
**影響**: サービス停止
**リスク**: 高
**対策**:
- ✅ ユーザーごとのレート制限 (例: 10リクエスト/分)
- ✅ IPベースのレート制限
- ✅ キャッシュの積極的な利用 (24時間)
- ✅ バッチ処理によるAPI効率化
- ✅ クォータ消費量のモニタリングとアラート

#### 脅威 D-2: 大量データ処理によるリソース枯渇
**説明**: 大量のチャンネル分析リクエストでサーバーリソースを枯渇
**影響**: レスポンス遅延、サービス停止
**リスク**: 中
**対策**:
- ✅ リクエストサイズの制限 (例: 最大50チャンネル/リクエスト)
- ✅ タイムアウトの設定 (30秒)
- ✅ 非同期処理とキューイング
- ✅ Vercel の Function タイムアウト設定

#### 脅威 D-3: スプレッドシート肥大化
**説明**: 無制限なデータ蓄積でスプレッドシートが肥大化し、処理が遅延
**影響**: パフォーマンス低下
**リスク**: 低
**対策**:
- ✅ データ保持期間の設定 (例: 1年)
- ✅ 古いデータの自動アーカイブ
- ✅ 読み取り行数の制限
- 📝 ユーザーへのデータサイズ警告

---

### E: Elevation of Privilege (権限昇格)

#### 脅威 E-1: IDOR (Insecure Direct Object Reference)
**説明**: 他ユーザーのスプレッドシートIDを指定して不正アクセス
**影響**: 他ユーザーデータの閲覧・改ざん
**リスク**: 致命的
**対策**:
- ✅ スプレッドシートIDとユーザーIDの関連性チェック
- ✅ Google Sheets API の権限チェック (ユーザーのトークンで実行)
- ✅ リソースアクセス前の所有権検証
- ✅ 直接的なIDパラメータの使用を避ける (セッションから取得)

#### 脅威 E-2: 水平権限昇格
**説明**: 同じ権限レベルの他ユーザーのデータにアクセス
**影響**: プライバシー侵害
**リスク**: 高
**対策**:
- ✅ 全APIエンドポイントでユーザーIDの検証
- ✅ セッションのユーザーIDとリクエストのユーザーIDの一致確認
- ✅ Google OAuth トークンのスコープ制限

#### 脅威 E-3: 管理者機能の不正利用
**説明**: 将来的な管理者機能への不正アクセス
**影響**: システム全体の制御
**リスク**: 低 (現時点では管理者機能なし)
**対策**:
- 📝 管理者機能実装時のロールベースアクセス制御 (RBAC)
- 📝 管理者操作の監査ログ
- 📝 管理者アカウントの分離

## データフロー図 (DFD)

```
┌──────────┐         HTTPS          ┌───────────────┐
│  ユーザー  │ ──────────────────────▶ │   Next.js     │
│ (Browser) │ ◀────────────────────── │  App Router   │
└──────────┘    Cookie (HttpOnly)    └───────┬───────┘
                                              │
                     ┌────────────────────────┼────────────────────────┐
                     │                        │                        │
                     ▼                        ▼                        ▼
              ┌─────────────┐         ┌─────────────┐         ┌─────────────┐
              │  NextAuth   │         │   Sheets    │         │   YouTube   │
              │   (OAuth)   │         │     API     │         │     API     │
              └──────┬──────┘         └──────┬──────┘         └──────┬──────┘
                     │                       │                       │
                     ▼                       ▼                       ▼
              ┌─────────────┐         ┌─────────────┐         ┌─────────────┐
              │   Google    │         │   User's    │         │   YouTube   │
              │   OAuth     │         │   Drive     │         │   Public    │
              └─────────────┘         └─────────────┘         └─────────────┘
```

### 信頼境界

1. **ブラウザ ↔ Next.js**: 信頼できない (HTTPSで保護、入力検証必須)
2. **Next.js ↔ Google APIs**: 信頼できる (OAuth トークンで認証)
3. **ユーザー ↔ スプレッドシート**: 信頼できない (ユーザーが直接編集可能)

## リスク評価マトリクス

| 脅威ID | 分類 | 影響度 | 発生確率 | リスクレベル | 優先度 |
|--------|------|--------|----------|--------------|--------|
| S-1 | Spoofing | 高 | 低 | 中 | P2 |
| S-2 | Spoofing | 高 | 中 | 高 | P1 |
| T-1 | Tampering | 高 | 中 | 高 | P1 |
| T-2 | Tampering | 中 | 中 | 中 | P2 |
| I-1 | Info Disclosure | 中 | 中 | 中 | P2 |
| I-2 | Info Disclosure | 中 | 中 | 中 | P2 |
| I-3 | Info Disclosure | 高 | 高 | 致命的 | P0 |
| I-4 | Info Disclosure | 高 | 中 | 致命的 | P0 |
| D-1 | DoS | 高 | 高 | 高 | P1 |
| E-1 | Privilege Escalation | 高 | 中 | 致命的 | P0 |

**優先度定義**:
- P0: 即座に対策が必要 (リリースブロッカー)
- P1: リリース前に対策が必要
- P2: リリース後早期に対策
- P3: 将来的に対策

## セキュリティ要件まとめ

### 必須対策 (P0/P1)

1. ✅ **ログへの機密情報出力防止** (I-3)
2. ✅ **クライアントサイドへのシークレット露出防止** (I-4)
3. ✅ **IDOR対策** (E-1)
4. ✅ **セッショントークン保護** (S-2)
5. ✅ **APIリクエスト改ざん防止** (T-1)
6. ✅ **レート制限** (D-1)

### 推奨対策 (P2)

1. ⚠️ **エラーメッセージの適切な処理** (I-1)
2. ⚠️ **スプレッドシートデータのサニタイズ** (T-2)
3. ⚠️ **監査ログの実装** (R-1)
